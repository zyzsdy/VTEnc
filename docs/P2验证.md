# P2 原生文件转码验证

日期：2026-11-16。设备 Apple M6，系统 macOS 27.2.1 / arm64。Debug、Release 构建通过；最低部署目标仍为 macOS 13，没有在旧系统上运行验证。

## 实现范围

- MP4/MOV 原生解封装、显式 VideoToolbox 硬解、H.264 / HEVC 硬编、AVAssetWriter 原生封装。解码和编码均要求硬件，在会话建立及处理结束后核验实际后端。
- 视频通过 AVSampleCursor / AVSampleBufferGenerator 读取压缩样本。解析公开 SPS / hvcC / av1C，保留 4:2:0 的 8/10-bit 与 range；为 `hev1` 重建 VideoToolbox 接受的 HEVC 格式描述，不重写压缩数据。
- B 帧输入按 DTS 边界和 PTS 重排，最多保留 32 个待显示帧。压缩输出最多一个在途帧，回调仅保留样本或异常，调度线程负责写出。输出不启用 B 帧。
- 保留逐帧显示 PTS、VFR 间隔、源视频尺寸、像素宽高比、SDR 色彩信号和显示变换。所有时间轴运算使用 CMTime 整数有理数，不以平均帧率重建时间戳。
- 默认复制第一条音轨，`--no-audio` 关闭。音频从 AVAssetReader 取得原始压缩样本，连同 priming、trim 等原生附件交给 AVAssetWriter，不经过重编码；字幕、章节、附件和其他音轨不复制。
- 取消、非法输入、硬件错误、写入失败均不发布成品。使用同目录临时目录及不覆盖目标的原子发布，Objective-C 异常转为带上下文的 C++ 诊断。

## 使用 video_samples 的实际结果

全部原始媒体来自 `tests/video_samples`，没有替换或修改原样片。另以 VFR 样片无重编码派生一个带 90° 显示变换的 MOV。共 9 个成功转码用例、1152 帧输出：

| 输入 | 输出 | 视频帧数 | 验证 |
| --- | --- | --- | --- |
| `decode/h264_8bit.mp4`，关闭异常音轨 | H.264 High 8-bit / MP4 | 82 | 硬解、硬编、完整帧数和精确 PTS |
| `decode/h264_10bit.mp4`，关闭音轨 | HEVC Main10 / MP4 | 82 | 实际 H.264 10-bit 硬解，保持 10-bit |
| `decode/hevc_8bit.mp4` | H.264 High 8-bit / MP4 | 82 | `hev1` 描述适配及精确 PTS |
| `decode/hevc_10bit.mp4` | HEVC Main10 / MP4 | 82 | `hev1` 描述适配及精确 PTS |
| `decode/av1_8bit.mp4` | HEVC Main 8-bit / MP4 | 82 | 实际 AV1 硬解，输出位深正确 |
| `decode/av1_10bit.mp4` | HEVC Main10 / MP4 | 82 | 实际 AV1 10-bit 硬解，输出位深正确 |
| `timing/vfr_h264_aac.mp4` | HEVC Main / MP4，AAC 复制 | 220 | 视频 PTS、音频包和 PCM 精确匹配 |
| 同一 VFR 样片 | HEVC Main / MOV，AAC 复制 | 220 | 同上，覆盖 MOV 封装 |
| VFR 无重编码派生的旋转 MOV | H.264 High / MP4，AAC 复制 | 220 | MOV 输入、旋转变换、音频与时间轴 |

每个成功用例都独立检查 Profile、实际像素位深、尺寸、像素宽高比、源已声明的 SDR 色彩信号、逐帧 PTS 和输出 DTS；用 FFmpeg 严格解码完整输出。H.264 未显式写出 video-signal-type 时，limited range 按规范默认语义判定，不把 FFprobe 的 unknown 文本当成 full range。

三个音频复制用例各有 **518 个 AAC 包**：逐包 SHA-256 和 PTS 完全匹配，音轨时长、首包 skip-samples 一致；独立解码后的 PCM 字节数与 SHA-256 也完全一致，覆盖编码延迟和尾部裁剪。

VFR 输出全部 **220 帧**的 PTS 与源显示顺序精确相等，第一帧为 `6000/30000 = 0.2 s`，最后一帧为 `365000/30000`。10 / 15 / 30 fps 三个区段保留，音轨仍从 0 开始、可听时长 12 秒，没有分别归零导致的 A/V 偏移。

本机确认了 H.264 10-bit 和 AV1 10-bit 的硬件解码；这只是该设备和配置的真实结果，不据此承诺所有 M 系列、系统版本或格式组合均支持，更不意味着支持 H.264 10-bit 输出。

## 明确拒绝与异常路径

- `hdr/` 下的 HLG AV1、HDR10 HEVC、Dolby Vision P5/P8.1 四个样片均明确拒绝；没有按普通 SDR 转码或丢弃 HDR 元数据后报告成功。
- `deinterlace/` 下普通 TFF 交错、3:2 Telecine 两个样片从 H.264 SPS 识别为交错编码，明确要求后续反交错管线。
- 原始 `decode/h264_8bit.mp4` 的前两个 AAC 包 PTS 都是 `1024/44100`，DTS 分别为 `0/44100` 和 `1024/44100`。直接交给音频分组/封装会产生重叠或丢包风险，因此在音频复制前检查存储包时间轴并明确报错；`--no-audio` 可完整转码其 82 帧视频。没有默认修补或隐藏这个源文件问题。
- 已有目标文件不被覆盖；截断 MP4、源 10-bit / 请求 8-bit 不匹配均失败且不发布成品。
- 在视频已编码并创建临时封装输出后发送 SIGINT，返回 130，无成品和临时目录残留。
- 通过进程文件大小限制触发真实 AVAssetWriter 写入错误，返回 1，临时输出清理。

这覆盖了样片目录中全部 13 个原始文件：7 个 SDR 输入用于正向检查，4 个 HDR 和 2 个交错输入用于拒绝检查。

## 复现

```bash
source build/tools/bin/activate
cmake --preset dev
cmake --build --preset dev
ctest --preset dev -R '^vtenc.cli$'
ctest --preset dev -R '^vtenc.timeline$'
ctest --preset dev -R '^vtenc.bitstream$'
python3 tests/transcode_hardware.py --vtenc build/dev/vtenc
# 共享编码配置调整后的 P1 回归
python3 tests/encode_hardware.py --vtenc build/dev/vtenc
cmake --preset release
cmake --build --preset release
```

只执行相关检查，没有运行全量 CTest 或样片准备工具的全量校验。无硬件时间轴测试覆盖精确编辑偏移、PTS/DTS 差值、压缩数据不变、无效时间和不支持的裁剪/变速编辑；CLI 检查覆盖容器参数冲突。P1 七个硬编用例及异常检查也通过。

最终 P2 报告与产物：`build/hardware-tests/p2-osoqtduu/verification.json`。P1 回归报告：`build/hardware-tests/p1-5qgc13g2/verification.json`。这些生成物不提交；脚本每次创建新的独立目录。FFmpeg/FFprobe 只负责测试、严格解码和无重编码派生 MOV，不是 VTEnc 的运行依赖。

## 当前限制

仅支持一个逐行 SDR 视频轨、4:2:0 的同位深传递，以及一个兼容容器的音轨复制。视频颜色、位深、缩放、反交错、音频转码、复杂编辑列表、Seek / Trim 和多音轨选择均不在 P2。

P2 处理完整存储视频帧。旧文件粗粒度声明时长可能落在最后一帧边界之前，因此保留整个尾帧；明显裁剪存储帧或改变播放速度的编辑映射会报错。初始单段编辑偏移用于统一电影时间轴，不能把声明轨道时长与全部显示帧跨度混为一谈。

未验证其他设备、旧 macOS、任意编解码器属性组合、长时间吞吐量或热稳定性；没有测量并承诺零拷贝。SIGKILL 或系统崩溃可能残留临时目录。音轨兼容性最终由原生封装器检查，不会静默转码为其他音频格式。
