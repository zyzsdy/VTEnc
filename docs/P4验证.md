日期：2026-11-17。实现与本机阶段验收完成，包括真实 FFmpeg / VSPipe 8/10-bit 生产者。下列结果均为本次实际执行，不以源码可达性代替验证。

## 环境

- 原生 Apple M6 / arm64，macOS 27.2.1（26B131）。
- Apple Clang / Command Line Tools，CMake dev preset。
- FFmpeg / ffprobe 9.0.2，运行时链接 avformat 63 / avcodec 63 / avutil 61。
- VapourSynth / VSPipe R81（Homebrew 81_1，API R4.3），仅用于集成测试；按用户提供的 `all_proxy` 临时代理完成依赖下载，未写入项目或 shell 全局配置。
- 编码会话实际 EncoderID：H.264 `com.apple.videotoolbox.videoencoder.ave.avc`；HEVC `com.apple.videotoolbox.videoencoder.ave.hevc`。
- Homebrew FFmpeg 库部署目标为 macOS 27.0，链接器提示其高于项目的 macOS 13；本次不能证明产物能在 macOS 13 运行。沿用已有依赖环境限制。

## 能力、错误和取消

- H.264 8-bit / HEVC 8-bit / HEVC 10-bit 的固定 1920×1080 能力查询成功，JSON 返回配置、Profile、像素格式、EncoderID、OS 版本和属性名。明确 `session_prepared`、`frames_encoded:false`、`property_values_validated:false`；不把这些查询描述为完整编码验证。
- JSON 每行都能独立解析；序号连续，编码任务只有一个终态且位于最后；文件编码 stdout 为空，stdout 码流不混入 JSON 或文本。
- Y4M 总长度未知，整个任务包括完成事件的 percent/ETA 均为 null；已知视频长度在真正完成后才为 100%。
- 像素负载截断、残缺 FRAME 头、只有文件头、缺失/零/重复帧率、非 4:2:0 格式、缺失颜色解释、10-bit 缺失 chroma location 都非零退出；未发布目标文件，临时文件清理。
- Y4M 默认解码模式和 `--avhw` 均要求用户显式选择 `--avsw`，不消费后重试。
- 在 stdin 尚无头部、以及已经处理帧后上游停滞时，SIGINT 均在 5 秒测试超时内退出 130。前者没有伪造硬件后端确认。
- stdout 下游关闭得到 `failed` / 退出码 1；stdout 填满后 SIGINT 得到 `cancelled` / 130，无需下游先排空才能退出。
- 已存在文件内容保持不变；不支持非 seek 的 MP4 stdout 封装报错，FFmpeg 诊断保持在 JSON 内。
- 生产者在完整帧 EOF 后返回 7，VTEnc 仍能合法完成已收到的 37 帧。这验证的是协议限制：上层必须结合两个退出码，VTEnc 不虚构生产者状态。
- 真实 `interlaced_tff_h264.mp4` 强制硬解仍返回 OSStatus -12911；JSON 保留整数错误码。默认模式报告 attempt 1 硬解失败，attempt 2 软解后经 Metal Bob 输出 360 帧，唯一 completed 指向 attempt 2。
- 已有 stdout 回归同时验证硬解/软解、输入输出双管道、startup retry、stdout 开始后的晚期硬解失败禁止重试、封装错误、EPIPE、阻塞写取消和文件日志通道。

## 验证范围与复现

`tests/status_y4m_hardware.py` 默认强制运行真实 VSPipe 8/10-bit 脚本，检查生产者退出码、37 帧完整码流、逐帧 PTS、位深和 Y/U/V 数值。默认测试缺少 VSPipe 会失败，不静默跳过；仅显式 `--skip-vspipe` 才允许运行其余检查，并在报告中标注未验证。本次最终报告没有跳过这部分。

本次只验证上述设备和配置，不泛化为所有 M 系列或所有 VideoToolbox 属性组合的能力。VapourSynth 不是 VTEnc 的运行依赖，也未把 Python、FFmpeg CLI 或软件视频编码器加入产品运行路径。生产者在帧边界失败无法仅凭 Y4M EOF 识别，是已验证的格式限制；上层仍须汇总生产者/VTEnc 退出状态。
