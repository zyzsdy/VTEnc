# P4 调用协议与 Y4M 帧管道

协议版本：`schema_version: 1`。对应 `--json-status`，2026-11-17。

## 通道与生命周期

所有编码任务信息均写 **stderr**。普通模式在 TTY 上用回车更新同一行，重定向时逐行记录；显示帧数、媒体时长、耗时、平均 fps 和媒体速度，长度已知时显示百分比和 ETA。`--json-status` 将进度、C++ 诊断、FFmpeg 日志及终态统一写为 UTF-8 JSON Lines，每个对象后恰有一个 `\n`，即时 flush，无 ANSI 控制符。调用方必须并行读取 stdout/stderr，不能等待进程退出后才读取有界管道。

JSON 模式也适用于 `--version` 和 `--check-features`，结果仍写 stderr；普通查询保留 stdout 文本输出。`--help` / `--check-device` 不接受该参数。JSON 参数错误返回结构化 `failed` 和退出码 2。

stdout 在 `-o -` 时仅含媒体数据；文件编码时为空。输出到 stdout 必须指定 `-f` / `--output-format`，且封装器必须支持不可 seek 输出。

每条事件都有 `schema_version`、`event`、从 0 连续递增的 `sequence`。接入方忽略未知字段和未来新增事件，遇到不支持的主协议版本明确拒绝。事件顺序：

| 事件 | 含义 |
| --- | --- |
| `version` | 程序版本、平台；单独查询 |
| `capabilities` | 指定 Codec / 位深 / 1920×1080 的硬件会话准备结果、实际 EncoderID、OS 版本、属性名和功能状态；单独查询 |
| `start` | 版本、OS、请求配置；开始编码任务 |
| `attempt` | 当前尝试号及选中的解码后端；raw / synthetic 为 `none` |
| `session` | 实际编码尺寸、像素格式 FourCC 数值、硬编后端与 EncoderID、会话配置；此时不声称已编码帧 |
| `progress` | 已送入输出模块的硬编码帧统计；首帧及之后约每 250 ms 更新，有新输出帧才更新 |
| `diagnostic` | 上下文消息及存在时的原始 OSStatus（从异常类型传递，不解析消息文本）；包括解码重试诊断 |
| `completed` | 排空、封装收尾、关闭，以及文件模式的防覆盖发布全部成功；退出码 0 |
| `failed` | 致命错误，包含消息、OSStatus 或 null；运行错误退出码 1、参数错误 2 |
| `cancelled` | SIGINT 取消，退出码 130；未完成文件清理，已写 stdout 字节无法撤回 |

编码任务只有一个终态，并且它是最后一个事件。正常调用方应同时要求 **`completed` + 进程退出码 0**，不能仅凭 100%、EOF、会话准备成功或已经收到码流判定成功。进程被 SIGKILL 或外部依赖异常终止时可能没有终态，不能据此合成成功。

自动硬解失败后，只有可回读输入且尚未开始 stdout 封装才重试；新 `attempt` 的帧数、媒体时长和速度统计从头开始。总任务耗时不清零。`session` 的 `hardware:true` 始终指视频编码器，解码后端另由 `decoder` 标注；软解不会改变硬编约束。

P7 在 `start` / `session` 配置的 `filter` 内增加 `yadif: {enabled: bool, bob: bool}`；场序继续使用 `field_order`（0=auto、1=tff、2=bff）。`bob` 是 YADIF 内部的场倍率，不等同于独立的 `filter.bob`。配置记录实际归一化场序；协议主版本仍为 1，旧调用方按约定忽略新增字段。

## 进度字段

| 字段 | 语义 |
| --- | --- |
| `attempt` | 从 1 开始的编码尝试号；参数失败时为 0 |
| `frames` | 当前尝试已由输出模块接受的编码帧数；Bob / IVTC / YADIF / CFR 后的输出帧数 |
| `pts` | 最近输出帧绝对 PTS，`{value,timescale}`；尚无帧时为 0/1 |
| `media_time` | 最近帧结束时间减首帧 PTS；整数有理数，不包含源非零起点 |
| `elapsed_seconds` | 进程任务观察器创建以来的 steady-clock 秒数 |
| `attempt_elapsed_seconds` | 当前尝试以来的秒数；包含打开输入和初始化成本 |
| `fps` | `frames / attempt_elapsed_seconds`，平均输出速度 |
| `speed` | `media_time / attempt_elapsed_seconds`，媒体实时倍速 |
| `video_bytes` | 已接受的视频压缩 sample 负载字节；不含音频、封装头，不等于文件大小 |
| `total_time` | raw 精确帧数/帧率，或 avformat 视频流提供的有效 duration；未知为 null |
| `percent` | 已知长度的媒体进度；处理中上限 99.9，发布成功才为 100；未知长度始终 null |
| `eta_seconds` | 根据当前尝试平均速度估算；总长度未知或尚无进展为 null |
| `bytes` | 仅成功终态是最终文件/stdout 字节数；取消时为 null |
| `output_complete` | 只有成功终态为 true |
| `audio_packets` / `gpu_frames` | 成功终态的复制或 AAC 编码音频包数、Metal 完成帧数；取消时为 null |

Y4M 总帧数不在格式头中，**包括 Y4M 文件输入在内，均不将按文件大小估算的 duration 当作总长度**。未知长度任务即使完成，`percent` / `eta_seconds` 仍为 null，使用 `completed` 判断结果。等待上游、硬件调用或下游背压期间没有新帧时不发心跳，不将没有更新等同于任务失败。

示例（字段节选，实际事件还包括 sequence 等字段）：

```json
{"schema_version":1,"event":"progress","attempt":1,"frames":30,"pts":{"value":29029,"timescale":30000},"media_time":{"value":30030,"timescale":30000},"elapsed_seconds":0.5,"fps":60,"speed":2.002,"total_time":null,"percent":null,"eta_seconds":null}
```

P5 在 schema 1 中追加 `config.avsync`（vfr/cfr/forcecfr）、`dar`（value/timescale 比值或 null）、`audio_codec`（copy/none/aac）、`audio_backend`（audiotoolbox 或 null）、`audio_bitrate`（bits/s 或 null）、`audio_sample_rate`（显式 Hz 或 null）。源采样率保留时该配置字段是 null；实际 AAC 后端、采样率、声道、priming 和排空后的有效样本数目前作为 diagnostic 提供。`fps` 在 CFR 中是请求的目标帧率；进度顶层 `fps` 仍然是处理速度。CFR 输出帧数与输入帧数可以不同，forcecfr 的媒体时间可能超过源时长不足一个周期。

JSON 保留有效 UTF-8，控制字符和引号正常转义；无效 UTF-8 字节按 `\u00XX` 表示。所有时间基和帧计数为整数，消费端应使用足以容纳 64 位整数的解析类型；展示用 fps、速度和秒数是浮点数，不用于重建时间轴。

## 配置与能力边界

`start.config` 包含输入/输出、选择的封装器（空串表示自动）、视频 Codec / 位深 / Profile、raw 帧数与帧率（或 P5 显式目标帧率）、解码模式、音频模式、GOP、有效码率或 Quality、固定硬件/重排/实时约束，以及全部滤镜参数和默认值。avformat 尚未读取的源宽高、帧数为 null，默认 VFR 的 fps 为 null；`session.width/height/pixel_format` 给出解析和滤镜后的实际输入到编码器的配置。`session.config.decoder` 已解析为当前尝试的后端。

滤镜 matrix / transfer / primaries 使用 `command_line.hpp` 中的 H.273 数值，`2` 表示 auto（BT.601 使用 6）；其余枚举如下：

| 配置项 | 数值 |
| --- | --- |
| range | 0 auto，1 limited，2 full |
| field_order | 0 auto，1 tff，2 bff |
| input_chroma | 0 auto，1 left，2 center，3 top-left |
| ivtc.expand | 0 auto，1 on，2 off |
| tonemap.mode | 0 none，1 hable，2 mobius，3 reinhard，4 bt2390 |

`capabilities.config` 列出该次探测实际采用的 Codec、Profile、位深、尺寸、像素格式及硬件约束。基础探测创建会话、设置 Profile、准备会话并核验硬编。P8 另用独立会话逐组合设置码控/GOP/速度倾向；所有查询均不编码帧。`probe_level:session_prepared`、`frames_encoded:false`、`property_values_validated:false` 明确区分属性枚举和真实编码。属性名中可能有内部键，不能将其当成可透传的 CLI 选项。

任务成功终态的 `probe_level:frames_encoded` 表示此任务确实产生了硬编帧，不代表独立验证过所有码流语义或其他参数组合。`features` 分别标注 available、available_requires_avsw、unverified、not_implemented、unsupported_by_design；这些实现状态不代替指定配置的真实探测。

## Y4M 输入

无需 `--y4m` 开关，使用 avformat 自动识别，必须提前显式指定 `--avsw`。不设置 `--input-res` / `--frames`，这些参数属于紧密打包 NV12/P010 raw 路径；P5 仅在显式 `--avsync cfr|forcecfr` 时接受目标 `--fps`，它不改写 Y4M 源帧率。

```bash
set -o pipefail
ffmpeg -v error -i input.mp4 -an -pix_fmt yuv420p -f yuv4mpegpipe - |
  build/dev/vtenc --avsw -i - -o output.mp4 --json-status \
    --vpp-colorspace matrix=bt709:auto,transfer=bt709:auto,colorprim=bt709:auto,range=limited:auto \
    2>status.jsonl

vspipe -c y4m input.vpy - |
  build/dev/vtenc --avsw -i - -o output10.mp4 --codec hevc --output-depth 10 \
    --input-chroma-loc left \
    --vpp-colorspace matrix=bt709:auto,transfer=bt709:auto,colorprim=bt709:auto,range=limited:auto
```

示例仅适用于实际为 BT.709 limited-range、相应 chroma location 的素材；不要把这些示例值当作缺失元数据时的自动猜测。Y4M 不能完整传递 VapourSynth 帧属性。调用方须通过已有 `--vpp-colorspace` FROM:auto 输入解释和 `--input-chroma-loc` 明确源颜色；已存在的头部 range/chroma 标记可被读取。缺少必要解释、未知/零帧率或不支持像素格式立即失败。

当前支持偶数尺寸的 planar 4:2:0 8-bit 和 10-bit little-endian，软解模块负责转换存储布局为 NV12/P010，滤镜由 Metal 执行，视频编码仍是原生 VideoToolbox 硬编。4:2:2、4:4:4、RGB、其他位深不在支持范围。Y4M 是 CFR，按帧序号和头部 F 整数有理数生成时间轴，`FRAME` 扩展不会导致按字节偏移计算 PTS 的漂移。

avformat 负责识别、读头及解封装；只在其 Y4M 路径补充严格校验：跳过不必要的读帧探测，检查不完整 FRAME 头/负载，拒绝原库对缺失帧率使用 25 fps 的默认值。stdin 使用有界 AVIO 缓冲及 poll 读取，以支持上游停滞时 SIGINT；非 seek 的 Y4M 输入应通过 `-i -` 传入。输入消费受编码/输出背压约束，不读入完整影片。

干净 EOF 表示收到的所有完整帧已经结束。如果生产者失败时恰好停在帧边界，Y4M 自身无法证明本来还应有多少帧。GUI 必须检查生产者与 VTEnc **双方**退出状态；shell 使用 `pipefail`，进程管理器应同时取消/回收生产者。不要将 VTEnc 的 `completed` 当作上游任务成功的证明。

## 参考与验证

状态显示字段和节流方式参考 [NVEnc rgy_status.cpp](https://github.com/rigaya/NVEnc/blob/master/NVEncCore/rgy_status.cpp)（MIT），未复制上游实现；本协议不冒充 NVEnc 协议。Y4M EOF/时间轴限制依据 [FFmpeg yuv4mpegdec.c](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/yuv4mpegdec.c) 检查并实测；VSPipe 调用使用[官方输出文档](https://www.vapoursynth.com/doc/output.html)。VTEnc 不内嵌 VapourSynth，也不增加其运行时依赖。

显式集成测试：`python3 tests/status_y4m_hardware.py --vtenc build/dev/vtenc`，需要 FFmpeg / ffprobe / VSPipe 和真实 Apple Silicon。具体环境及结果见 [P4 验证](P4验证.md)。

### P6 配置扩展

schema_version 继续为 1，新增字段采用向后兼容的可忽略扩展：`config.subtitles` 按叠加顺序列出文件、字体目录／文件／替代族、offset_ms、opacity、white_nits 和 clip；`config.color_tags` 单独记录仅标签操作，`config.hdr_metadata` 记录模式及显式整数元数据。模式枚举与 CLI 配置类型一致：0=auto、1=clear、2=preserve。

能力 `features` 增加 libass/Metal 外部 ASS/SSA 烧录、独立标签、HDR10 静态元数据及按封装参数集策略；仍然是实现范围，不代表每台机器的所有组合通过了码流验证。libass 和 CoreText 字体诊断统一进入 stderr diagnostic 事件，找不到字形会产生 failed 终态，不能把缺字输出当成功。

## P8 编码控制增量（schema 1）

新增 `config.rate_control`（abr/quality/cbr/vbr）、`max_bitrate`（bits/s）、`bitrate_window_seconds`、`vbv_buffer_bits`、`vbv_duration_seconds`、`preset`（default/performance/quality）和 `force_keyframes`（已解析的输出帧号列表）。不适用或未显式指定者为 null；VBR 指定 max 而未指定缓冲大小时，实际设置 2.5 秒，见原生设置事件。`bitrate` 保持表示当前模式的目标 bits/s，Quality 模式为 null。

新增 `encoder_settings` 事件，发生于会话准备和硬件核验后、首帧提交前。`requested_settings` 是本次请求的公开控制属性，`settings` 是逐项回读的有效属性，`probe_level=session_prepared`。设置被拒绝或关键控制回读不一致即失败。`ExpectedFrameRate` 属于提示，允许系统规整并额外输出 diagnostic；它不会改变实际有理数帧时间。事件不代表已经编码，更不代表质量或速度收益。

`capabilities.control_probes[]` 的每项包括 `name`、`enumerated`、`stage`、`settings`、`encoder_id`、`error` 和 `os_status`。依次尝试 api/create/set/prepare/hardware/readback；成功为 `session_prepared`，失败保留所在阶段和原始诊断。候选基线为查询选择的 Codec / 位深、1920×1080、30 fps、GOP 60、目标 5 Mbit/s；上限候选为 8 Mbit/s / 1 秒，VBR/VBV 候选为 8 Mbit/s / 2 秒。每个组合独立建会话，不缓存失败，也不把硬件忙固化为不支持。每项固定 `frames_encoded=false`、`bitstream_validated=false`；顶层 `property_values_validated=false` 仍表示未验证任意值组合。

`capabilities.native_presets` 报告 `SupportedPresetDictionaries` 回读结果与 OSStatus，`probe_level=read_only`、`cli_exposed=false`。字典包含多项设置，不能直接当作 `--preset` 的含义。`features.encoder_controls` 为 `implemented_requires_session_probe_and_job_validation`；`strict_gop` 明确无公开 API，`frame_reordering` 为管线禁用，其余高级覆盖为未开放。GUI 应按具体 probe 和当前配置提供候选选项，编码成功与真实输出验证仍须单独判定。

ABR 窗口 / VBR 包络超限、指定关键帧未兑现或帧号超出 EOF 都输出 `failed`（exit 1），不触发解码回退。stdout 可能已有部分码流，不能以收到媒体字节判断成功。
