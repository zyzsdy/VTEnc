# P5 时间轴、DAR 与 AAC 验证

日期：2026-11-17。本文记录本机实际编码和独立解析结果；支持范围不由芯片名称推断。CLI 语义及示例见 [README](../README.md#p5-时间轴dar-与-aac)。

## 环境与依赖

- 原生 Apple M6 / arm64，macOS 27.2.1（26B131），Apple Clang 21，CMake dev preset。
- FFmpeg / ffprobe 9.0.2；链接 avformat 63、avcodec 63、avutil 61、swresample 7。
- 视频实际后端：H.264 `com.apple.videotoolbox.videoencoder.ave.avc`，HEVC `com.apple.videotoolbox.videoencoder.ave.hevc`。每个成功任务检查硬件会话及实际压缩帧，另用 FFmpeg 完整解码验证。
- 音频直接调用系统 AudioToolbox C API，AAC-LC / ABR / High；本机查询到 priming 为 2112 个采样，代码不硬编码该数值。AudioConverter 不接受显式设置 PrimeMethod，因此使用实际查询的编解码延迟；其他设置检查返回值并读回。
- 本机 Homebrew FFmpeg 启用 GPL / version3，不能描述为 LGPL-only；许可说明见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。库的部署目标为 macOS 27.0，高于项目配置的 macOS 13，链接器给出警告；本轮未验证旧系统兼容性。

## 运行方式

从仓库根目录执行，构建工具已安装在本地 `build/tools/bin`：

```bash
export PATH="$PWD/build/tools/bin:$PATH"
cmake --preset dev
cmake --build --preset dev
ctest --preset dev -R '^vtenc.cli$'
ctest --preset dev -R '^vtenc.(cfr|timeline|status)$'
python3 tests/p5_hardware.py
python3 tests/status_y4m_hardware.py --skip-vspipe
```

没有执行全量测试。硬件脚本只能在真实 Apple Silicon 上显式运行；它们不加入普通 CTest。测试素材的视频由 VTEnc 硬编或取自既有样片，FFmpeg 只负责独立解析/解码、音频素材生成和重封装，不使用软件视频编码器。

本次 CLI、CFR、既有 timeline 和 status 检查全部通过。P5 报告记录 32 个用例：23 个成功转码、8 个预期失败、1 个取消；另包含 raw DAR、stdout 提前拒绝和输出防覆盖断言。60 秒重采样用例输出 2,880,015 个有效采样，与独立结果一致。相关报告保存在本地忽略目录：

- `build/hardware-tests/p5-pt0c77hy/verification.json`
- `build/hardware-tests/p4-wp3n_g8v/report.json`（`vspipe_verified:false`）

| --- | --- |
| VFR → CFR | 30000/1001 硬解、7 fps 软解；逐包检查非零原点、精确有理数 PTS、输出帧数和末帧截短 |
| forcecfr | 24 fps 软解；末帧保持完整周期，尾点延长不足一周期 |
| 默认 VFR | 既有 VFR / AAC 样片保持视频 PTS、时长和音频压缩内容 |

| 长时间轴 | 单测独立计算跨 30 小时的 30000/1001 时间点，无逐帧浮点累加；不宣称实际编码了 30 小时视频 |

## AAC 采样与同步

测试使用已知长度、不同频率的 mono/stereo PCM 源。输出 MOV/MP4 由 Apple `afconvert` 独立解码，MKV 由 FFmpeg 解码；比较有效采样数和首尾窗口的 PCM 对齐，信噪比阈值为 25 dB。并独立解析 MOV 编辑列表，检查原点、有效时长、媒体起始采样和播放速率，不以“可播放”或总容器时长代替同步检查。

- 48 kHz mono、44.1 kHz stereo，保持采样率；44.1 ↔ 48 kHz stereo 双向重采样。
- 64 个有效采样的极短音频、非 1024 整倍数尾部，以及 MKV 的 skip/discard metadata。
- 2,646,013 个 44.1 kHz stereo 源采样（约 60 秒）转 48 kHz，输出采样数与独立重采样一致，验证排空与末端对齐。
- AAC → AAC；音频从 0.1 秒、视频从 0.2 秒开始，并与 30000/1001 CFR 组合；正起点 AAC 再次转码；0.01 秒小偏移。
- 编码包时间轴包含实际 priming，尾包记录 padding。MOV/MP4 保留完整媒体包时长，以编辑列表描述有效播放区间；发布前 AudioFile API 回读有效采样表。其他容器回读音频包数、格式、PTS 和 skip/discard。

## 拒绝、清理与回归

- CLI 检查新增参数、互斥关系、显式目标帧率、raw/压缩输入边界。
- 缺音轨、不支持的码率、5.1 声道、未显式重采样的 32 kHz、FLAC/MKV 音频时间戳断裂、不可表示的 SAR 均返回错误。
- TS 丢失 AAC 首尾裁剪信息、仅视频封装器无法接收音轨时，不发布文件并清理临时目录；AAC stdout 在写入前拒绝。
- 已存在目标文件保持原内容；长素材 120 fps forcecfr + AAC 在出现进度后 SIGINT，退出 130，不发布文件，临时目录清理，只有 cancelled 终态。
- Y4M / JSON 协议相关回归另行执行，包含 8/10-bit FFmpeg 生产者、PTS、像素、EOF、背压和取消；本轮没有重复 VSPipe 验收。

## 明确边界

- 第一条音轨，AAC-LC、mono/stereo、44.1/48 kHz、文件输出；不隐式混音、变速、补静音、调整码率或改用其他编码后端。默认仍复制音轨。
- MOV/MP4 有效音频起点必须非负，生成的尾部 moov 不超过 64 MiB。其他容器不按名称白名单选择，以实际封装及回读结果为准。
- 本机 FFmpeg 对部分正起点或极短 AAC 编辑区间的解码存在首尾采样解释差异。原生解码和独立编辑列表检查通过，并不意味着任意 FFmpeg 调用会得到相同 PCM 长度。MOV 家族 AAC 输入因此额外读取系统 AudioFile 有效采样数，媒体包仍由 avformat 解封装、libavcodec 解码；这种输入要求本地、系统解析器可读的文件。无法取得准确 metadata 时明确失败。
- CFR 使用保持/丢弃已有画面，不做运动插帧；DAR 只改变比例标签，不增加黑边或旋转像素。
- 本轮没有验证所有 Apple 芯片、所有系统版本、所有 AAC 码率或封装器；能力查询中的 available 表示功能已实现，真实组合仍以实际会话和码流结果为准。

## qaac 与项目边界

[qaac v3.00](https://github.com/nu774/qaac/releases/tag/v3.00) 已提供原生 macOS 构建支持，可编译独立 CLI。它是 Apple 音频编码器的命令行前端，没有供 VTEnc 直接依赖的稳定 `libqaac` 公共接口。NegativeEncoder 可以继续编排外部 qaac；本项目直接使用 AudioToolbox，不复制 qaac 代码、不增加 qaac 可执行文件依赖，也不承诺和 qaac 默认设置逐字节一致。
