# P1 硬编最小闭环验证

日期：2026-11-16。设备查询返回 Apple M6，系统 macOS 27.2.1 / arm64。Debug、Release 均通过 CMake Presets 构建，部署目标保持 macOS 13；没有在旧系统上运行验证。

## 交付范围

原生 VideoToolbox 完成合成 / 原始 NV12、P010 输入的 H.264 / HEVC 硬编码。创建会话时要求硬件编码器，在准备后和实际排空后分别核验 `UsingHardwareAcceleratedVideoEncoder`。没有软件视频编码路径，也不调用 FFmpeg 进行生产编码。

支持平均码率目标、原生 Quality、GOP 上限和整数有理数帧率。所有输入限定 BT.709 limited-range SDR、逐行、无帧重排。输出为 Annex B 及原始回调时间戳 CSV，不包含 MP4/MOV、音频或 HDR。

## 执行与结果

从仓库根目录执行，使用已有构建工具环境：

```bash
source build/tools/bin/activate
cmake --preset dev
cmake --build --preset dev
ctest --preset dev -R '^vtenc.cli$'
ctest --preset dev -R '^vtenc.bitstream$'
cmake --preset release
cmake --build --preset release
python3 tests/encode_hardware.py --vtenc build/dev/vtenc
```

只执行上述相关检查，没有运行全量 CTest 或已有视频素材全量校验。硬件验证不加入默认 CTest；缺少硬件、FFprobe 或 FFmpeg 时直接失败，不跳过后伪装通过。

| 合成 / H.264 8-bit | 1920×1080 | 65 | 30000/1001 | High / yuv420p | 0.205 |
| 原始 NV12 / H.264 8-bit | 318×178 | 17 | 24000/1001 | High / yuv420p | 0.230 |
| 合成 / HEVC 8-bit | 1920×1080 | 65 | 30000/1001 | Main / yuv420p | 0.134 |
| 原始 NV12 / HEVC 8-bit | 318×178 | 17 | 24000/1001 | Main / yuv420p | 0.164 |
| 合成 / HEVC 10-bit | 1920×1080 | 65 | 30000/1001 | Main 10 / yuv420p10le | 0.549 |
| 原始 P010 / HEVC 10-bit | 318×178 | 17 | 24000/1001 | Main 10 / yuv420p10le | 0.364 |
| 合成 / H.264 单帧 | 320×180 | 1 | 30/1 | High / yuv420p | 0.003 |

六个常规用例分别使用平均码率 2000 kbit/s（合成）或 Quality 0.7（原始），GOP 上限 16。单帧用例使用默认平均码率 5000 kbit/s、GOP 1。误差单位是对应位深的亮度码值，用于发现输入行跨度、P010 位对齐或 range 错误，不作为画质评级。

验证内容：

- 所有编码任务成功前确认实际硬件后端；独立 FFprobe 检查 Profile、像素格式、尺寸、BT.709 色彩信号、limited range、帧数、无 B 帧及 GOP 上限。
- FFmpeg 严格解码全部输出，另将首帧亮度与已知原始渐变比较。FFmpeg 仅作为独立测试工具，不链接到 VTEnc。
- CSV 的每一帧精确满足 `PTS = index × fps_den / fps_num`、`duration = fps_den / fps_num`；检查帧号、关键帧标记及字节范围完整覆盖输出。本机回调 DTS 未指定，CSV 留空，没有以 PTS 伪造 DTS。
- 65 / 17 帧覆盖 8 帧批次的最后一个不完整批次；单帧覆盖最小排空；原始输入多准备一帧，确认显式帧数限制。
- 已存在输出、已存在 CSV、过短原始输入、FIFO 输入均被明确拒绝；非对齐宽度原始输入验证了逐行拷贝。
- 限制进程输出文件大小，触发真实写入错误，确认返回 1、没有发布结果、临时文件清理。
- 等待已产生压缩数据后发送 SIGINT，确认排空已提交帧、返回 130、没有成功输出或临时残留。

无硬件的 `vtenc.bitstream` 检查使用本项目生成的 SPS/PPS：对 1/2/4 字节 NAL 长度前缀及逐字节分散的 `CMBlockBuffer` 验证 Annex B 输出；拒绝截断、零长度、越界 NAL 和错误 PTS；模拟发布竞争，确认既有文件不被覆盖且已发布 CSV 回滚。

详细运行报告、原始测试帧和编码结果保留在 `build/hardware-tests/p1-aitw0zii/`，不提交生成物。重新执行脚本会创建新的独立目录，并生成 `verification.json`。

## 边界

上述结果只验证这些设备、系统和配置，不证明任意 Profile、尺寸、硬件型号或 macOS 版本可用。`--check-features` 仍然只准备固定配置会话和枚举属性，不提交编码帧。

Annex B 没有容器级 PTS/DTS，不能把裸码流解复用器猜测的帧率或时间戳作为回调时间轴的证据。本阶段验证的是配套 CSV 中保留的真实回调时间戳；P2 再验证封装后的时间轴和 A/V 同步。

8 帧批次排空旨在约束内存并建立可验证生命周期，尚未进行吞吐量调优或长时间稳定性测试。两个输出文件分别原子发布，不提供系统崩溃时的跨文件事务保证；SIGKILL 等无法处理的终止可能留下临时文件。
