# P8 编码控制验证

日期：2026-11-17。P8 按公开 API 和实际输出完成有限扩展；以下结论只覆盖已列配置，不泛化到其他 M 系列、系统、分辨率或任意属性组合。

## 环境与复现

- Apple M6 / Mac mini，24 GB，原生 arm64；macOS 27.2.1（26B131）。
- 当前 Command Line Tools SDK；C++20 / macOS 13 部署目标。VBR / VBV / 原生预设查询有 SDK 与 macOS 26 可用性保护。
- 本机 Homebrew 依赖构建目标是 macOS 27；本次不能证明可执行产物兼容 macOS 13。
- H.264：`com.apple.videotoolbox.videoencoder.ave.avc`；HEVC：`com.apple.videotoolbox.videoencoder.ave.hevc`。创建要求硬编，准备及编码完成后均核验实际硬件后端。

```bash
cmake --preset dev
cmake --build --preset dev --target vtenc vtenc_encoder_controls_test vtenc_status_test
ctest --preset dev -R '^vtenc.cli$'
ctest --preset dev -R '^vtenc.(encoder-controls|status)$'
python3 tests/p8_hardware.py
python3 tests/p8_io_hardware.py
```

硬件脚本不注册到默认 CTest。本次未运行全量测试。最终长片报告位于 `build/hardware-tests/p8-uy1l3s3g/report.json`；逐任务 JSONL、逐包尺寸、PSNR 日志和媒体保留在同目录。I/O 报告为 `build/hardware-tests/p8-io-ry4jlts4/report.json`（9 项：8 项完整编码、1 项 stdout 超限失败）。此前探索失败也保留在 `build/hardware-tests/p8-*`，不覆盖原始证据。

## 分层结果与开放范围

查询固定 1920×1080 / 30 fps，分别使用 H.264 High/NV12、HEVC Main/NV12、HEVC Main10/P010，AutoLevel。每个候选另建会话；原生属性组合基线为目标 5 Mbit/s、GOP 60、帧重排 false、RealTime false。ABR 上限是 8 Mbit/s / 1 秒；VBR/VBV 是 8 Mbit/s / 2 秒。三种 Profile 的七组候选均枚举、设置、准备、后端核验、回读成功。**查询没有提交帧**，JSON 中保持 `frames_encoded=false`、`bitstream_validated=false`。

| 计划项 | 会话及真实输出结论 | CLI / 集成决策 |
| --- | --- | --- |
| H1 CBR | `ConstantBitRate` 设置/回读成功；静态段填充，整段目标行为成立；局部窗口明显波动 | 提供 `--cbr`，命名和帮助明确原生目标算法，不保证逐帧或任意窗口恒定；文件输入要求显式 CFR |
| H2 ABR 上限 | `DataRateLimits` 接受，真实输出可能越界；H.264 1 秒样本通过，HEVC 1 秒纹理样本拒绝，三种 Profile 的 2 秒样本通过 | `--bitrate --max-bitrate [--bitrate-window]`；逐压缩样本检查，越界即失败，不能宣称硬件无条件维持上限 |
| H2 VBR / VBV | `VariableBitRate`、`VBVMaxBitRate`、`VBVBufferDuration` 可用；复杂度响应成立，常规样本缓冲包络通过；高熵突变可越界 | `--vbr [--max-bitrate --vbv-bufsize]`；max 使用 VBV 属性，不设置 DataRateLimits；包络超限失败 |
| H3 速度 / 质量 | 公开速度倾向 true/false 均接受并产生有效码流，实测速度/PSNR 见下表 | `--preset default/performance/quality`，只定义速度倾向的显式设置；没有 P1～P7 映射或固定收益保证 |
| H4 GOP / 定点帧 | 最大间隔与 `ForceKeyFrame` 请求得到同步样本，ffprobe 帧类型一致 | 保留 `--gop-len`，增加 NVEnc 格式 `--keyfile`；不提供 strict GOP |
| H4 禁止额外关键帧 | 枚举包含 StrictKeyFrameInterval 等内部键，但当前公开 SDK 没有对应公开常量 / 契约 | “API 不支持”，不用内部字符串键绕过，不提供 `--strict-gop` |
| H5 帧重排、Profile | 三种已开放 Profile 真实码流均正确，DTS=PTS、无 B 帧，AutoLevel | 维持关闭帧重排及 High/Main/Main10 AutoLevel，不开放精确 B 帧数 |
| H5 前瞻 / 参考帧 / Open GOP / Profile 与 Level 覆盖 | 无本轮明确扩展需求；未进行这些组合的真实输出验证 | 排除于本次有限交付，不宣称硬件不支持，也不作为可用能力发布 |

`SupportedPresetDictionaries` 三种配置都可回读，返回 Balanced、HighQuality、HighSpeed、ConsistentQuality；包含重排、前瞻、速度倾向和不同码控设置。当前管线逐显示帧排空，不能原样采用这些组合，所以仅作为诊断，不开放字典透传。H3 通过独立公开速度倾向实现，不将未编码验证的原生预设标为可用。

## 长片码流与码率

测试素材由脚本直接生成未压缩 NV12/P010，无软件视频编码：640×360、30 fps、900 帧（30 秒），前 10 秒静态梯度，中间 10 秒有纹理的二维移动，末 10 秒每秒硬切换。另有独立逐帧随机高熵突变素材，用于反例。码率模式基准目标 2000 kbit/s、最大 3000 kbit/s，VBR 缓冲 6000 kbit（2 秒）。

普通模式记录三个 10 秒段、每个逐帧滑动的完整 1/2 秒窗口、总码率、帧类型、关键帧、Profile、尺寸、位深及时间戳；ffprobe 独立解码读取，FFmpeg 严格完整解码。GOP 上限为 60；`--keyfile` 验证帧 0、37、299、300、451、600、899，分别覆盖普通帧、相邻关键帧、段边界和最后一帧。限码率长片使用自然 GOP，强制关键帧与限码率的组合另按通过 / 拒绝记录，不能凭任意多关键帧仍要求预算必然可满足。

CBR 结果，单位 kbit/s：

| Profile | 静态 10 秒 | 移动 10 秒 | 切换 10 秒 | 30 秒平均 | 最大 1 秒窗口 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H.264 High | 1906.809 | 2099.432 | 2027.467 | 2011.236 | 3525.576 |
| HEVC Main | 1899.822 | 2041.768 | 2045.363 | 1995.651 | 3637.808 |
| HEVC Main10 | 1899.822 | 2326.407 | 1762.401 | 1996.210 | 3963.152 |

最初尝试的“每个十秒段均在 ±10%”验收在 Main10 上失败（移动段 +16.3%、切换段 −11.9%），该失败没有被隐藏。最终开放的契约是**原生 CBR 算法请求与填充，不是十秒窗口恒定**；验证整段目标偏差不超过 ±10%、静态填充以及完整码流，并保留每个局部窗口观测。需要硬性上限的调用方使用受检查的 ABR 窗口或 VBR 包络；不能把 CBR 最大单秒值误解成目标值。

ABR 上限与 VBR/VBV：

| Profile | ABR 3000 / 1 秒 | ABR 3000 / 2 秒，最大 2 秒均值 | 原生 VBR，静态 / 移动段 | VBR + VBV |
| --- | --- | ---: | --- | --- |
| H.264 High | 通过，最大 2840.360 kbit/s | 2781.860 kbit/s | 14.038 / 2280.726 kbit/s | 完整输出和 6 Mbit 包络通过 |
| HEVC Main | 在 360/30 秒拒绝：390044 > 375000 字节 | 2717.620 kbit/s | 23.339 / 2346.513 kbit/s | 完整输出和 6 Mbit 包络通过 |
| HEVC Main10 | 在 360/30 秒拒绝：416798 > 375000 字节 | 2733.820 kbit/s | 24.214 / 2295.733 kbit/s | 完整输出和 6 Mbit 包络通过 |

另对三个 Profile 分别执行 900 帧低复杂度 ABR 1 秒上限和 VBR/VBV，全部成功并独立核对输出。高熵反例中，ABR 在 PTS=302/30 时窗口达到 520096 字节（预算 375000）；VBR 在 PTS=301/30 时突破 6000000 bit 缓冲容量。最终实现均报错，文件不发布，不重试解码。此前未加检查的探索版本确实输出了超限码流，证明仅设置、回读及可解码不足以成立限码率保证。

限制检查使用原始硬编样本，不包含封装、音频、适配补写的参数集等开销。ABR 使用 `[t,t+window)` 半开滑窗；VBV 使用压缩包大小与整数有理数时间差计算泄漏桶包络，不做浮点时间累计。该检查不等于完整 HRD/CPB 认证，不保证总文件或网络发送带宽。每个 VBR max 请求都显式设置缓冲时长（未给容量时为 2.5 秒），并核对回读。

短片另对三种 Profile 运行 1920×1080、90 帧、30000/1001、CBR 5000、quality 倾向。Profile、位深、尺寸、PTS/DTS、完整解码均通过。`ExpectedFrameRate` 回读为 29，日志保留请求 29.970029970… 和有效提示 29；输出仍精确为 30000/1001，没有改变实际帧时钟。其约 4838 kbit/s 的单秒峰值也不应被描述成每个窗口精确 5000。

## 预设的实际设置与观测

`default` 不设置速度倾向；`performance` 只设置 `PrioritizeEncodingSpeedOverQuality=true`，`quality` 只设置 false。两者保持 `RealTime=false`、重排 false、ABR 2000、相同源及关键帧请求。下表为一次完整任务的墙钟吞吐与独立解码 PSNR，包含输入、编码和文件写入，不能当作纯硬件性能基准。

| Profile | performance fps / PSNR dB | quality fps / PSNR dB |
| --- | --- | --- |
| H.264 High | 919.0 / 41.126 | 905.6 / 41.228 |
| HEVC Main | 771.2 / 47.269 | 601.9 / 49.739 |
| HEVC Main10 | 673.4 / 46.698 | 755.1 / 52.108 |

Main10 中 quality 反而更快，说明名字只是原生偏好，不保证速度排序。不同设置实际码率也不同，不能据此宣称同码率质量收益，更不能推导三个固定档位或与 NVENC 的等价关系。

## 路径、错误和协议

长片脚本共 39 项：34 项成功完成并核对码流，5 项明确失败且不发布文件（两项 HEVC 1 秒窗口、超出 EOF 的关键帧、高熵 ABR、高熵 VBV）。真实输出验证包含三种 Profile 的 `--avhw` 文件转码及 CBR；失败记录保持一次尝试，不因编码约束失败触发软件解码重试。

补充脚本覆盖：

- 30→60 forcecfr 后，H.264 / HEVC Main10 的输出帧 0、37、179 为关键帧，180 帧的精确 PTS/DTS 保持。
- 原始 NV12 + Metal Bob 的同一帧号请求，180 帧 / 60 fps，验证请求作用于输出而非输入帧号。
- Y4M stdin → 显式软解 / Metal 色彩解释 → H.264 / HEVC Main10 原生 VBR/VBV → Matroska stdout，帧 0、37、89 为关键帧，90 帧完整解码；stdout 无诊断文本。
- VBR 未指定 `--vbv-bufsize` 时回读 2.5 秒；分数帧率 CBR 事件同时记录请求和回读提示，真实 PTS/DTS 仍正确。
- stdout 高熵超限：返回失败、attempt=1，允许已有部分媒体字节，不发 completed，不拼接重试流。

纯规则检查覆盖码率互斥、kbit/s 与 kbit 换算、max 与目标大小关系、ABR/VBR 属性隔离、非法预设、keyfile 缺失/空白/重复/逆序/越界、CRLF；CoreMedia 合成包检查整秒滑窗边界、VFR 空隙、单包越界、不同有理数时间基的 VBV 累积及关键帧未兑现。P4 schema 1 增量记录配置、逐项控制探测和请求/回读事件，不将会话准备冒充真实编码。

## API 与 CLI 依据

- [Apple ConstantBitRate](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_constantbitrate)：原生 CBR、帧率提示、填充与属性互斥。
- [Apple VariableBitRate](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_variablebitrate) 与 [VBVMaxBitRate](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_vbvmaxbitrate)：VBR 不能叠加 AverageBitRate/CBR/DataRateLimits；上限走独立 VBV 路径。
- [Apple DataRateLimits QA1958](https://developer.apple.com/library/archive/qa/qa1958/_index.html)：滑动窗口数据率，非逐帧峰值；本次同时记录硬件违反该请求的反例。
- [Apple SupportedPresetDictionaries](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_supportedpresetdictionaries) 与本机公开 `VTCompressionProperties.h`：原生预设只读诊断；速度倾向和关键帧仅绑定公开 API。
- [NVEnc 选项](https://github.com/rigaya/NVEnc/blob/master/NVEncC_Options.en.md)、[NVEncCmd.cpp](https://github.com/rigaya/NVEnc/blob/master/NVEncCore/NVEncCmd.cpp)：参考 `--cbr` / `--vbr` / `--max-bitrate`、`--vbv-bufsize` 容量单位、`-u/--preset` 和 `--keyfile` 格式；未复制解析器实现，不接受无等价硬件语义的 NVENC 专有参数。
