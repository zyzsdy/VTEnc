## 实现语义

`--vpp-yadif [mode=auto|tff|bff|bob|bob_tff|bob_bff]` 与 Bob、IVTC 互斥。单倍保留先到场、重建另一场；场倍按时间先后输出两场。自动模式按逐帧元数据保留逐行画面，场倍自动模式将逐行画面复制到两个半帧区间。显式场序用于解释逐行编码的交错栅格；与另一个显式场序冲突时在 I/O 前报错。

复用 HEVC 单场配对与 RFF 展开，之后进入三帧 YADIF 窗口，不执行 IVTC 的五去一或场匹配。配对与展开的实际空间奇偶优先于全局覆盖。RFF 尾场只有一个输出、采用纯空间重建；HEVC 孤立场由场配对阶段重建后直接保留。结构边界、逐行／交错切换和场序切换不借用另一段的时间参考；首尾缺邻帧时使用当前帧。没有新增基于画面差异的场景切换检测器，普通画面切换沿用 YADIF 的时间差约束。

输入完整栅格要求 NV12/P010、偶数宽、高度至少 8 且为 4 的倍数；上下场色度位置必须相同。每平面按原采样网格独立处理，UV 方向搜索不能混用 U/V。整数 8/10-bit 码值计算，P010 写回高 10 位、低 6 位为零。保留 NVEnc 的方向搜索顺序、条件 ±2 搜索、完整中心时间差及 clamp 边界；这不同于部分 FFmpeg YADIF 公式，也不等于 NVEnc 整条 16-bit 色彩管线的逐像素等价移植。下游仍统一转换到 left 色度位置。

支持 avformat 文件与 `--avsw` Y4M 文件／stdin，紧密打包 raw／synthetic 入口明确拒绝。Y4M 的显式颜色与色度解释要求仍适用。输出缓冲池上限 6 个、软解时序源缓冲上限 10 个；每个 GPU 命令完成并核对状态后才交给下一阶段。滤镜错误不是 `HardwareDecodeError`，不会触发软解重试。

## GPU 数值与质量

`vtenc_yadif_test` 通过 **134 组像素／参考检查、8 组质量检查、100 组场结构／时间轴／错误检查**：

- NV12/P010、limited/full、TFF/BFF、第一／第二输出场、独立 UV 通道、非整线程组尺寸与填充 stride；确定性高频数据覆盖完整 10-bit 精度，逐像素与独立标量参考相等。
- 静止、运动、斜线、细线、画面突变、黑／白极值、首帧／末帧复制参考、单帧输入、逐行直接保留；P010 低位为零。
- 静止一像素水平线保持原值。另用静止细线与匀速斜线运动的已知逐场真值，汇总 8/10-bit、TFF/BFF 与两场，在去掉图像边界的亮度区域得到 SSE：YADIF **0**、线性 Bob **225486228**、未处理交织图像 **29406600**。这是特定合成图案的回归证据，不能推导所有视频都优于 Bob，也不是压缩码流 PSNR 或通用质量排名。
- 非零起点、VFR、1/2/3/11 帧首尾排空；精确半帧 duration、无间隙重叠、总结束时刻不变。
- 混合逐行／交错、场序变化、结构边界；RFF 奇偶尾场、完整帧重复 2/4、HEVC 上下场配对／孤立尾场；不去掉真正交错曝光，不把孤立场再拆成两个输出。
- 缺场序、缺末帧 duration、非法 RFF、非法输出时间基、颜色元数据变化、上下场色度网格不一致、取消均有明确失败或取消结果。

## 真实编码与同步

共 **24 个成功编码用例**，全部核验实际硬件编码器，输出严格解码并检查逐行标志、帧数／时间轴；带计量的任务峰值 RSS 最大 **62,078,976 字节**。

| 路径 | 结果 |
| --- | --- |
| 原始 720×480 交错 H.264，显式软解，auto / tff | 各 180 帧；H.264 8-bit 与 HEVC Main10 输出 |
| 同源 bob / bob_bff | 各 360 帧；精确场倍时间轴 |
| 原始交错 H.264，默认自动解码 | 硬解失败明确诊断后，从头软解一次；360 帧 |
| 硬解 220 帧非零起点 VFR + AAC，auto / bob / bob_tff | 220 / 440 / 440 帧，裁剪缩放后视频 PTS 精确，AAC payload、PTS、priming/trim 和解码 PCM 不变 |
| 硬解 VFR + YADIF + forcecfr + ASS | 720 帧，60000/1001 固定周期与非零起点精确，字幕在最终时间轴渲染 |
| 原生 10-bit Y4M TFF / BFF，软解成 P010，bob | 12 → 24 帧，HEVC Main10 严格解码、逐行标志正确 |
| 10-bit Y4M stdin → bob → HEVC MPEG-TS stdout | 24 帧；stdout 纯 TS，stderr 全部 JSON，含归一化 YADIF 配置且只有一个成功终态 |
| H.264 8-bit / HEVC 10-bit 混合逐行、RFF、hard 栅格，各软解／硬解、auto／bob | 8 项，分别 30 / 60 显示帧，未执行电影去重；视频区间和音频包时间／负载一致 |
| HEVC 8/10-bit，TFF/BFF 半高单场，软解／硬解、bob | 4 项，9 个源场 → 9 个完整高度逐行输出，含孤立尾场，时间区间精确 |

原始交错 H.264 的强制硬解会话返回 **OSStatus=-12911**（`VTDecompressionSessionCreate [hardware required; woven source]`），没有输出文件。这是当前样本／设备的硬解限制，不能将软解接入或重试成功称为原始样本硬解成功。混合/RFF 与 HEVC 单场用例使用硬件生成并经独立语法检查的载体，分别记录其真实硬解成功，不外推到所有交错编码格式。

额外验证非法场几何在 GPU 阶段失败且不触发自动软解重试、Y4M 缺颜色解释被拒绝、SIGINT 返回 130、无发布文件和临时文件残留。测试脚本不下载素材、不调用软件视频编码器。

P7 不增加 AFS、NNEDI、BWDIF、cadence lock、物理旋转或高质量缩放预设；不扩大已有 HDR／音频／封装支持范围。接口与调用示例见 [README P7](../README.md#p7metal-yadif-运动自适应反交错)。
