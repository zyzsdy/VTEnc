# P9：VTEnc 独立构建与分发

## 本次范围

按本次要求，只修改 VTEnc，不修改 NegativeEncoder。交付 `0.1.0-alpha.1`
macOS ARM64 预发布包、可重建的独立依赖、构建／打包脚本、对应源码与许可证。
这完成 P9 的 VTEnc 分发工作，不代表完整 M10 接入完成。

NegativeEncoder 后端、GUI 参数／音频映射、版本及进度解析、进程树管理与三条
GUI 工作流的集成验收仍留在该仓库后续处理。

## 构建与依赖边界

- 本机：Apple M6（arm64），macOS 27.2.1，Apple Clang 21，SDK 由 xcrun 选择。
- `release` preset：本机 Release 构建，动态链接已安装的 Homebrew 库。
- `distribution` preset：从独立 `build/distribution/prefix` 链接，发行物不依赖 Homebrew。
- FFmpeg 9.0.2、libass 0.17.5、FreeType 2.15.0、HarfBuzz 15.0.0、
  FriBidi 1.0.18、libunibreak 8.0；原始源码的 SHA-256 见 `scripts/dependencies.json`。
- FFmpeg 禁用 GPL、nonfree、version3、全部编码器、外部库自动发现，以及不使用的
  avdevice、avfilter、swscale。包装阶段再次检查实际 libavcodec 的 license、configuration
  和编码器迭代结果，拒绝打包含任何编码器或许可证不符的构建。
- 字幕库使用 CoreText 系统字体，不捆绑用户字体。FreeType 选择 FTL；FriBidi 不构建 GPL CLI。
- 将所有非系统动态库复制至 `lib/`，使用相对 install name；每个 Mach-O 均须为 arm64。
  发现 Homebrew 或依赖前缀以外的非系统动态库直接失败。

## 系统与签名声明

构建目标为 macOS 13.0；每个发行 Mach-O 的实际最低版本、动态库闭包、SHA-256、
编译器及源代码提交记录在 `BUILD-MANIFEST.json`。加载命令的最低版本不是旧系统实机验证。
本次只在 macOS 27.2.1 上验证，不声称 macOS 13～26 或其他 M 系列机型已完成运行验收。

本机 `security find-identity -v -p codesigning` 返回 0 个有效身份，因此首次预发布仅作
ad-hoc 签名并用 `codesign --verify --strict` 核验，**未作 Developer ID 签名或 Apple 公证**。
下载后的 Gatekeeper 限制不能用本地执行通过替代验证。`--identity`／`--notary-profile`
预留正式签名及公证入口，取得有效身份后须另行实测。

隔离验证将 ZIP 解压到仓库以外的临时路径，校验哈希与签名，清空运行环境变量，并用
macOS sandbox 显式拒绝读取源仓库、`/opt/homebrew` 和 `/usr/local`。它用于发现本机
依赖泄漏、路径不可迁移或运行时读取源码等错误；仍共享本机系统框架和字体，不等价于
在另一台全新安装的 Mac 上通过验证。独立干净系统与旧系统验收尚待完成。

## 发布内容

GitHub 预发布版本同时提供二进制 ZIP、精确对应的 dependency-sources 源码包及 SHA256SUMS。
ZIP 保留 `bin/`、`lib/`、完整文档、许可证与构建记录。无需 Python、FFmpeg CLI 或 Homebrew
即可运行 VTEnc；外部 FFmpeg／VapourSynth 管道生产者由调用方另行安装。

硬件能力仍按会话与真实码流分层。P8 的码率约束拒绝语义、关闭帧重排、High／Main／Main10
等边界不因发布打包改变；未开放项不对调用方宣称支持。
